# Мини-приложения Telegram для риелторов

Один движок на всех клиентов. У каждого риелтора своя папка с данными, свой бот и свой сервис заявок.

```
engine/              движок: стили и логика, общий для всех (правим только мы)
shared/photos/       фото и планировки общего каталога, одна копия на всех
clients/_template/   заготовка нового клиента
clients/demo/        демо-клиент, на нём проверяем изменения движка
clients/evgeniy/     Евгений, копия живого приложения из репозитория 1
worker/              код сервиса заявок и ответов бота (Cloudflare Worker)
```

Движок перенесён из живого приложения (репозиторий 1): разделы Новостройки / Коттеджные посёлки / Побережье, страницы посёлков и домов, планировки, карты, заявки через бота. Клиент видит то же самое, только со своим именем и контактами.

Адрес приложения клиента: `https://jonieao25-create.github.io/Rieltor/clients/<id>/`

## Как добавить клиента

1. Скопировать папку `clients/_template` в `clients/<id>`, где `<id>` — латиница без пробелов, например `ivan`.
2. В `clients/<id>/data.js` в блоке `settings` поменять `clientId`, ник риелтора, заголовки и цвет, а в блоке `privacy` вписать ФИО риелтора полностью (оно показывается в политике конфиденциальности). Каталог объектов уже общий; лишние объекты можно удалить.
3. `index.html` в папке клиента не править: он одинаковый у всех.
4. Создать бота в @BotFather. Menu Button и Direct Link: адрес приложения клиента.
5. Сервис заявок: в Cloudflare создать новый Worker (например `leads-ivan`), вставить код из `worker/index.js`, вписать переменные и секреты из `worker/wrangler.toml`. Адрес Worker вписать в `leadEndpoint` клиента.
6. В Cloudflare → Storage & Databases → KV создать отдельное хранилище клиента (например `replies-ivan`). В Settings → Bindings его Worker добавить KV binding с точным именем `REPLIES`. Один KV нельзя делить между клиентами.
7. Добавить обычные переменные `AGENT_NAME` (имя в автоответе) и `BOT_LINK` (ссылка кнопки каталога). При необходимости весь стандартный текст заменяется переменной `SECRETARY_TEXT`.
8. Подключить бота: открыть `https://<адрес worker>/setup?key=<WEBHOOK_SECRET>`, ответ должен быть «Webhook was set». Повторять после изменения списка webhook-событий.
9. Риелтор открывает бота, нажимает «Запустить» и пишет `/myid`. Бот отвечает числом; его вписать в секрет `MANAGER_ID`.
10. В Telegram риелтора открыть Настройки → Telegram Business → Чат-боты, подключить созданного бота и разрешить ему отвечать в личных чатах. Бот проверяет, что подключение принадлежит именно `MANAGER_ID`.
11. Проверить с другого аккаунта: первое сообщение получает автоответ и кнопку каталога, второе сообщение в течение суток — нет. Риелтору должно прийти служебное уведомление.
12. Открыть Mini App с другого аккаунта, перейти в раздел и карточку, затем отправить `/stats` боту с аккаунта риелтора. Отчёт доступен только `MANAGER_ID`.

## Бот-секретарь

Общий Worker умеет отвечать от имени подключённого Telegram Business-аккаунта:

- любой ещё не записанный в KV собеседник считается новым;
- после любой активности обеих сторон собеседник считается знакомым 20 суток;
- новому собеседнику ответ приходит в любое время;
- знакомому — только с 20:00 до 07:00 по Калининграду;
- одному чату ответ отправляется не чаще раза за 24 часа;
- риелтор получает уведомление, кому и почему ответил секретарь.

Стандартный пример для Светланы:

> Здравствуйте! Я Светлана, риелтор по недвижимости Калининграда. Сейчас не могу ответить, напишу вам в ближайшее время. А пока можете посмотреть каталог недвижимости 👇

Отключение: Telegram Business → Чат-боты → отключить бота. После отключения
проверить с другого аккаунта, что автоответ больше не приходит. Токен бота при
этом отзывать не требуется; если токен раскрыт, его нужно немедленно отозвать в
@BotFather и заменить `BOT_TOKEN` в Cloudflare.

## Статистика

Движок отправляет события `open`, `section` и `view` только при запуске внутри
Telegram. KV хранит дневные записи 40 дней. Команда `/stats` владельца показывает:

- открытия и уникальных посетителей за сегодня, 7 и 30 дней;
- пять наиболее просматриваемых объектов за 30 дней;
- просмотры разделов;
- пять последних посетителей за сегодня и вчера.

Ошибки аналитики не блокируют каталог и заявки. Из-за модели Cloudflare KV
суточный лимит и одновременные счётчики являются best-effort.

## Изменения движка

Правки в `engine/` сразу получают все клиенты. Сначала проверяем на `clients/demo/`. После правки увеличиваем `?v=` в ссылках `index.html` клиентов, иначе Telegram покажет старую версию из кэша.

Новые объекты из живого приложения (репозиторий 1) переносятся сюда вручную: блок объекта в `data.js` клиента и фото в `shared/photos/`.
